# Native Inworld Realtime PCM speech sessions

`pipecat-inworld-realtime` implements a distinct Inworld WebSocket session actor
and native paired speech pipeline. It does not route through the Grok/OpenAI
client, Python, a sidecar or a speech SDK. The facade feature is
`pipecat/inworld-realtime`.

## Declared profile

- Mono signed little-endian PCM16 input and generated speech output at independently
  configured 8, 16, 24, 32, 44.1 or 48 kHz. Pipeline `StartFrame` rates must match;
  use a native upstream/downstream resampler for another rate. Neither enum
  serialization nor this crate claims G.711 support.
- Provider-owned semantic/server VAD, or explicit locally driven turns. Default
  semantic VAD has low eagerness and automatic response/interruption enabled.
- Initial text history, generated/input transcripts, session settings, usage,
  typed local function calls, final tool results and interruption cancellation.
- One owned connection per processor. Rebuild the app/pair/session to reset;
  disconnect never reconnects, replays history/audio, or retries inference.

Pinned defaults are `openai/gpt-4.1-mini`, voice `Clive`, TTS `inworld-tts-2`, STT
`inworld/inworld-stt-1`, and 24 kHz PCM. They reproduce the source configuration,
not a guarantee of current provider entitlement, model or voice availability.

## Public construction path

`InworldApp::new(config, context, local_tools, output)` constructs the exact
native topology used by the runnable example and the local pipeline tests:

```
integrity ingress → paired user → InworldRealtimeProcessor → ToolExecutor
                  → result relay → caller's output → paired assistant
```

The returned `pipeline`, `pipeline_config`, `pair`, `provider` and `outcomes`
provide the ordinary core runtime and diagnostics. Start with
`app.start().await`, which admits the initial context without inference before
returning `InworldRunningApp { worker, pair, provider, outcomes }`. Its startup
barrier establishes local ordering, not provider acceptance. Directly consuming
the public raw `pipeline` bypasses this convenience and requires an explicit
no-run context intent before audio. Feed `InputAudio` or `UserAudio`
and explicit local speaking boundaries for manual mode. Input frames keep their
routing and speaker metadata downstream; local speaker IDs are not transmitted
as provider-recognized identities.

The constructor rejects non-text history, unbound/different offered schemas,
noninterruptible handlers and callbacks whose execution deadline exceeds the
response budget before opening a socket or invoking a callback. Use
`InworldLocalTool { schema: FunctionTool, handler: RegisteredTool }`; only a final
return is supported. Context tools take precedence when nonempty, otherwise
session tools are used, otherwise the supplied local schemas are offered.
Live settings cannot advertise a schema outside the constructor's registered set.
No reporting-tool, backend/frontend or intermediate-result route is exposed.
The ingress validates native carriers before user aggregation can transform
their public payload. Progressive tool carriers and continuation checkpoints are
rejected, rather than converted to ordinary user context.

The caller supplies output transport behavior. Default assistant history is
**generated transcript history**, not audible playback history. `LlmText` has
`append_to_context=false`; the corresponding `TtsText` is aggregated once.
This constructor does not fabricate playback receipts or claim generated bytes
were played. Custom low-level compositions remain responsible for the correct
paired topology and only final interruptible native ToolExecutor callbacks.

### Recorded PCM example

```
cargo run -p pipecat-inworld-realtime --example pcm_session -- --help
cargo run -p pipecat-inworld-realtime --example pcm_session -- --check-config
cargo run -p pipecat-inworld-realtime --example pcm_session -- --manual input.pcm output.pcm
cargo run -p pipecat-inworld-realtime --example pcm_session -- --server-vad input.pcm output.pcm
```

Set `INWORLD_API_KEY` explicitly to the provider's already encoded Basic
credential. The example reads only that requested variable, uses the production
endpoint and does not persist the credential. `--help` needs no credentials;
`--check-config` performs no connection. Session mode sends a bounded recorded
24 kHz mono PCM16 file and creates a new output PCM file; it never opens a media
device or public server. Server-VAD input must contain end-of-speech silence.
The example is not a browser/PSTN application or physical-playback qualification.

## Authentication and wire ownership

`InworldConfig::new(credential)` defaults to
`wss://api.inworld.ai/api/v1/realtime/session` and sends `Authorization: Basic
<credential>` without encoding the supplied string again. `AuthType::Bearer`
explicitly selects a supplied bearer credential. There is no token minting,
lookup, refresh or ambient credential fallback.

Each connection adds a new random `key=pipecat-realtime-...` and
`protocol=realtime`; the model belongs in the session, not the URL. Endpoint
userinfo, any caller query, fragments, non-WebSocket URLs and plaintext beyond a
literal loopback IP are rejected. TLS uses the existing rustls/WebPKI path;
redirects are not followed. Errors/Debug do not reveal keys, configured URLs or
raw provider payloads.

`session.created` triggers the initial `session.update`. Only an acknowledgment
matching the sent full session snapshot makes the connection ready. A
`conversation.created` event is not a readiness signal. Audio before readiness
is rejected; it is not queued for later replay. Each runtime session update also
requires a matching acknowledgment. A local queue admission or socket write is
not called provider acceptance.

`providerData` is copied before adding `metadata.sdk="pipecat-realtime"` and
`auto_tool_response=false`. Other bounded metadata/provider data is preserved.
A caller cannot enable automatic tool continuation. The stored input settings
are not modified by these reserved wire additions.

## Turns, chunks and interruption

Input is chunked into exact 60 ms PCM payloads, using integer sample arithmetic
(the supported rates all represent 60 ms exactly). A shorter aligned tail is
carried until the next input in server-VAD mode, as in the source. Manual stop
flushes it before `input_audio_buffer.commit` and exactly one response request;
a duplicate local stop without new audio does not infer again. Ordered End
flushes a remaining tail but does not invent a speech commit or new response.
Interruption, Cancel, disconnect and input pause discard the local residual;
paused audio is never replayed when admission resumes. A discarded tail alone
cannot cause an empty manual commit after resume. Full chunks already sent before
pause remain eligible for the current manual commit; pausing does not undo bytes
already transmitted.

Provider VAD start/stop proposes boundaries to the paired user's external turn
strategy; it does not also send a local commit/response for that turn. Manual
mode ignores late provider VAD boundaries. In manual mode interruption sends
input clear then response cancel; in provider mode ordinary interruption only
fences local output and clears obsolete continuation debt, relying on provider
VAD cancellation. An explicit low-level `CancelResponse` is a distinct
client-driven cancel request.

There is **no `conversation.item.truncate` action**. The pinned source only
clears local playback tracking. Local generation fencing must not be described
as removing interrupted generated audio from provider history.

Manual mode sends explicit JSON null at `audio.input.turn_detection`. This is an
intentional native safety difference: the pinned Python serializer uses
`exclude_none=True`, so its local `None` interpretation is not proof it always
transmits null. Omission is not accepted as native manual-mode intent.

## Context, settings and final tools

A first explicit context intent seeds once. A single user message is sent as
text; multiple text messages are packed into one user-history message, following
the source adapter. Service instructions override the initial context system
instruction. Later native trailing transcript snapshots are state-only and
cannot cause inference or consume an unrelated pending user's transcript.
Explicit typed user-text append/run causes are validated using the shared sealed native
provenance, not message counts or text-equality inference. Arbitrary live
replacement/deletion/transforms and opaque rich history are rejected.
Live message append controls accept only ordinary user text. The app rejects
tool-choice, generic tool-set and detailed-history mutation controls before they
can change paired context; use validated session settings to select among the
constructor's registered function schemas.

`UpdateSession` is a complete validated replacement snapshot, not generic merge.
The frame `session_properties` setting likewise replaces the whole session;
callers must provide the required PCM/model/VAD profile. Top-level model,
instructions/system_instruction and temperature changes start from the current
snapshot. Native typed temperature null omits the setting; instruction null
clears text. Audio rates and turn ownership cannot change within a processor.
Invalid updates do not alter the projected snapshot or admit partial wire work.

Tool execution happens only in the native `ToolExecutor`. Calls are bounded and
bound to a tracked item, call ID, offered name, completed JSON arguments and the
immutable response declaration. An omitted completion name is recovered only
from the matching tracked call. Unoffered, reused/conflicting or untracked new
calls fail closed, including a new declaration reusing a settled call ID. Late
argument delta/completion events for retired call IDs are ignored without
revalidating their payload and have no callback, settlement or wire authority.
The relay requires a validated native terminal receipt; raw matching
result data or a raw cancel request cannot prove successful settlement.

One final output/cancellation is delivered before the paired assistant's explicit
continuation. String results are preserved verbatim (already encoded JSON is
not encoded twice); other JSON results preserve null, false and zero rather than
inheriting the Python handler's truthiness conversion to the string `COMPLETED`.
Intermediate results are rejected without provider wire output. One owed
continuation may wait for an active response; a new response consumes preceding
delivered material, and interruption retires obsolete debt. No delayed async-tool
reliability or automatic second invocation is promised.

## Bounds and failure policy

Defaults: 64 command/event slots, 1 MiB encoded messages, 192,000 input bytes per
append action, 64 outstanding calls, 4,096 session calls/responses, 10 s
connect/readiness, 5 s operations, 120 s active response and 2 s socket close.
Limits are validated; WebSocket frames/messages/write buffers are finite.
Input transcript assembly and split output PCM samples are bounded. Odd output
tails, invalid base64, malformed known events, response failures, provider errors
and saturated queues fail closed with sanitized diagnostics. Unknown event types
are ignored with no protocol authority; a 64-event default lifetime budget
bounds tolerance and never renews readiness or an active response deadline.

The shared app startup envelope is twice the connect/readiness timeout plus an
operation budget. Its shutdown envelope is three response budgets plus two
operations and socket cleanup, so the default core 10/30-second envelope does not
silently preempt the provider contract. Callers may deliberately choose tighter
pipeline budgets, which can force cancellation rather than successful draining.

End settles admitted tools, waits for admitted settings acknowledgments, drains
an active response and any continuation already owed before End, then closes.
The low-level session rejects new ordinary work after Finish while still allowing
final tool settlement. New paired-assistant continuation requests generated
while End is draining are validated but not started; final results still reach
provider and local history. End is not a request to complete a new inference chain.
Cancel
fences output and drops stale queued audio/inference. A canceled shutdown wait
does not cancel the cleanup owner. Primary session failures and secondary socket
cleanup failures remain separately observable. There is no automatic retry after
an ambiguous write. Local tests use only literal-loopback peers and explicit fake
credentials, never real accounts, secrets or devices.
