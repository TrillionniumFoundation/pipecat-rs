# Native Gradium STT and TTS

Bounded, single-connection, mono PCM16LE recognition over real WebSocket I/O.
STT and TTS use separate source-pinned protocols and one shared bounded socket
transport. Neither path loads a Python runtime or Gradium SDK.

For multiplexed synthesis, use `GradiumTtsConfig`, `GradiumTtsClient`, and
`GradiumTtsProcessor`. See [TTS contract](TTS.md) for lifecycle, bounds and residuals.

## STT contract

- Sends `x-api-key` and `x-api-source: pipecat`, source-pinned setup, and waits for
  `ready` before accepting audio. Input rates 1–192 kHz map to the next 8/16/24 kHz
  rate, capped at 24 kHz, using the shared native streaming sinc resampler
- Audio is base64 JSON in complete 80 ms chunks. Arbitrary byte splits are
  retained, never padded into a PCM sample. Flush preserves resampler state and
  unsent partial chunks, as in the pinned source. EOS drains the filter and sends
  a final shorter, sample-aligned chunk; an incomplete PCM sample fails EOS
- Flush IDs are canonical decimal **strings**, matching the pinned Python
  implementation. Replies must echo the same string exactly. The current public
  Gradium reference instead declares integer IDs. This implementation deliberately
  does not coerce numeric IDs, and has not established live-provider compatibility
- A matching acknowledgment starts the source's fixed 100 ms trailing-text window.
  Text is joined with spaces into cumulative interim and final transcripts.
  Duplicate, unsolicited or mismatched acknowledgments fail the session; they
  cannot reset the timer or create another final
- Provider turns follow IDLE→ARMED→OPEN→ENDING, closest-horizon inactivity
  probability, inclusive stop threshold and the post-flush step cooldown. No next
  turn opens before the prior finalization. Malformed probabilities/horizons,
  nonmonotonic provided step indices and multiple text streams fail closed
- Provider proposals plus `SttMetadata` use the shared user aggregator's external
  strategies. Explicit application strategies and interruption policy still win.
  STT input recognition survives conversational Interruption, including the one
  generated by its own user-start proposal. Cancel, owner drop, mute and health
  generation changes fence callbacks and cancel their owned socket
- End/Stop drain admitted audio, send EOS and await remote terminal confirmation;
  the pipeline consumes final transcript events before forwarding its terminal.
  Cancel/drop abort instead. There is no hidden reconnect or audio replay
- Local threshold/horizon/cooldown changes are validated atomically and take effect
  on the next step. Active model/language/delay changes return `RequiresRestart`.
  Create a new session explicitly; this is narrower than source automatic reconnect
- Mute cancels/discards the current provider generation. Unmute establishes a new
  one without replay. Each connection has one configured speaker identity

`try_send_audio` success means local admission only. Statistics separately report
original-rate accepted bytes, resampled socket-written bytes, and bytes covered by
an exact flush acknowledgment or EOS. Bytes accepted but not written, and writes
interrupted by transport failure, do not imply completed transcription. Usage
metrics report newly finalized wire-audio duration, before the final frame.

## Bounds and security

Queue count/bytes, individual PCM/message/text sizes, total admitted audio, total
received message/control bytes and message count, JSON depth/nodes, connect,
read, write, flush, finish, close and session duration all have finite bounds.
Output saturation terminates the session with an error; queued callbacks are
discarded once failure is known, before bounded close cleanup. Successful EOS
still drains final events. Active flush/finish/read deadlines also bound nested
socket writes, and an already expired operation skips close waiting.
No reconnect/retry occurs after ambiguous audio delivery. Endpoint validation
rejects userinfo, queries, fragments, insecure public WS and private DNS answers;
explicit literal-loopback opt-in exists for local fixtures. DNS is resolved once
and those exact addresses are connected without proxy or redirects. TLS/HTTP
handshake reads are capped separately from WebSocket messages.

The crate redacts API keys, endpoint addresses, provider error/close bodies and
transcript text from its own Debug/error paths. **Disable both `tungstenite` and
`tokio_tungstenite` TRACE/DEBUG in real sessions.** Dependency logging can expose
credential-bearing handshake headers, audio/transcript payloads and close reasons;
this crate cannot sanitize dependency instrumentation. This remains a production
hardening gap, not a claim of end-to-end log secrecy.

## Scope and evidence

Source contract: Pipecat `af9f9da9d7afddaa8811c0e0251b32566c980bdf`,
`src/pipecat/services/gradium/stt.py` and `tests/test_gradium_stt.py` (static only).
Native integration base: `68f994a9fa3062e591f5ead31e39a24a69f360eb`.
Public protocol cross-check, read 2026-10-10:
https://docs.gradium.ai/api-reference/endpoint/stt-websocket and
https://docs.gradium.ai/guides/speech-to-text

The source's 12-frame default and enumerated delay values, 8/16/24 kHz output rate
selection and string flush IDs are preserved despite newer documentation options.
WAV/Ogg Opus, additional provider codecs, arbitrary JSON config, timestamp segment
assembly, translation/multi-stream attribution, source transparent reconnection,
provider-specific tracing callbacks and live service quality are not implemented.
The native sinc filter is not a bitwise substitute for source SOXR/resampy.
Local fixtures are protocol/lifecycle evidence only, not live recognition evidence.
